# 真实性核验：七条红线与核验动作

## 一、七条红线（命中任一 → 直接淘汰，不做平衡）

| # | 红线 | 判定要点 | 典型话术 |
|---|---|---|---|
| R1 | **先交钱** | 任何在拿到收益前就要支出的款项 | 押金、培训费、材料费、保证金、激活费、会员费、授权费 |
| R2 | **收入承诺** | 对收益做确定性或保底承诺 | 日入 300+、月入过万、保底收益、稳赚不赔、包回本 |
| R3 | **层级返佣** | 收益与拉人头挂钩，存在上下线层级 | 「发展下线」「三级分销」「团队计酬」——**两级以上即高度疑似传销** |
| R4 | **刷量类** | 靠虚假流量或出借账号获利 | 刷单、刷赞、刷播放、出租账号、出借收款码、代实名 |
| R5 | **垫资与跑分** | 需要用户自己垫付资金走账 | 代付货款、代收代付、帮转一笔账给返点 |
| R6 | **过度索取个人信息** | 索取与服务无关的高敏信息 | 手持身份证照、银行卡 + 验证码、人脸识别、征信授权 |
| R7 | **无主体信息** | 找不到可追责的运营方 | 查不到运营主体、无备案、无客服、无合同、只有微信群 |

**判定原则**：红线是**一票否决**，不做「虽然有风险但收益高」的权衡。任何一条命中，直接淘汰并在报告中留痕。

## 二、核验动作（按顺序执行）

### 1. 找官方口径

优先平台帮助中心、平台规则中心、官方广告文档，确认四项：准入门槛、费率、结算规则、违规条款。

**只有官方口径才算「已核实」**，第三方转述一律标注来源等级。

### 2. 核主体与域名

- 查运营主体名称、备案信息；
- 核对域名归属，排查同名山寨站；
- 主体信息查不到 → 记 R7。

### 3. 交叉验证

- 官方来源 ≥1 条 + 独立来源 ≥1 条；
- 两个来源说法打架 → 进入「口径冲突」分支（见第三节）。

### 4. 查退出机制

三个问题，任一答不上来就降级或淘汰：

- 能不能随时停止，不再投入？
- 已产生的收益能不能提出来？
- 提现门槛、周期、手续费是否写清楚？

> **提现规则说不清 = 一票否决。** 无法提现的收益数字没有意义。

### 5. 查负面

检索「项目名 + 骗局 / 维权 / 提现不了 / 投诉 / 跑路」。

负面信息要逐条核对**是否与当前项目同名同主体**，避免把同名不同项目的负面误判为本项目问题，也避免忽略真实投诉。

## 三、口径冲突处理（最重要的一环）

**触发条件**：同一事实，两个非官方来源给出不同说法。

**处理规则**：

> 不采信任何一方，标为「口径冲突 → 待补」，补法写「以 App 后台实际显示为准」。

**禁止行为**：

- ❌ 用「据说」「应该」「大概率」向用户下结论
- ❌ 取两个来源中看起来更有利的一个
- ❌ 折中取平均值
- ❌ 因为「多数来源这么说」就采信（若均为非官方来源）

**正确输出**：

```
判定：口径冲突 → 不采信任何一方，转待补
补法：打开 <平台> App → <菜单路径> → 以后台实际显示的开通条件为准
```

**为什么这条最重要**：副业领域最常见的割韭菜手法，就是用「据说 0 粉就能做」这类未经官方确认的门槛话术，把用户引向需要先付费的套路。这条规则省下的不是时间，是押金。

## 四、来源等级标注

报告中所有依据需标注来源等级：

| 等级 | 定义 | 用法 |
|---|---|---|
| **官方** | 平台官方帮助中心、规则中心、官方广告文档、政府公开信息 | 可直接作为结论依据 |
| **主流媒体** | 有编辑审核的正规媒体、权威行业站 | 可作交叉验证，不作唯一依据 |
| **第三方** | SEO 聚合站、个人博客、社群转述 | 仅作线索，**不可单独支撑关键结论**（门槛、费率、结算） |

**关键结论**（门槛、费率、结算周期、提现规则）必须满足：官方来源 ≥1 条。否则标待补。

## 五、淘汰留痕格式

每个被淘汰的候选，在核验结论表中写明：

```
判定：淘汰
命中红线：R1（先交钱）
触发话术：<原文引用>
依据：<来源等级 + URL>
```

留痕的意义：让用户能复核你为什么剔除它，而不是只看到一个被划掉的名字。
