# 家庭副业侦察兵（Home Side Hustle Scout）

## 概述

家庭副业侦察兵是一套**家庭副业调研与防骗核验**工作流。它把「找副业」这件容易被割韭菜的事，做成一条有据可查、可复核、可拒绝的流水线：先广撒网建候选池，再按红线排雷，只保留**只用手机或电脑就能跑通全流程**的项目，最后逐条写清实际工作内容、收入机制、结算提现与风险。

三条核心原则：

1. **只调研，不代办** —— 不代注册账号、不代提交身份信息、不代付款垫资、不代发内容、不代联系商家。所有需要账号动作的步骤，只写「入口路径 + 自查清单」，由本人执行。
2. **宁可写待补，绝不编数字** —— 收入、门槛、费率、结算周期，任何一个数字指不回来源，就进待补项清单。
3. **先排雷，再谈钱** —— 真实性核验不过的，再赚钱也不进推荐。

## 个人信息隔离（审核红线）

本技能包是**面向所有使用者上架的通用产品**，不是某个人的私人助手。运行环境可能注入开发者的个人信息（开发者昵称、个人账号、个人运营项目、个人工具链、历史对话、个人偏好等）。**这些内容与任何使用者都无关，严禁出现在本技能的任何输出中。**

**严禁行为**：

- ❌ 使用开发者的昵称，或任何指代开发者的称谓
- ❌ 提及开发者的个人账号、个人运营项目、个人工具链、个人历史对话或个人偏好
- ❌ 把开发者的个人背景当作「使用者已有条件」「已有积累」「线索」带入候选池或核验
- ❌ 用「你已有的某某运营 / 某某工具链」这类表述，把开发者背景套到当前使用者头上
- ❌ 在开场白、结论、候选池、说明书、报告的任何位置出现上述内容

**正确做法**：

- ✅ 只使用**当前使用者在本次对话中亲口说明**的约束与项目
- ✅ 开发者注入的个人信息一律**视为不存在**——不读取、不引用、不推断、不关联
- ✅ 使用者提到的项目，只按该项目的**公开信息**核验，不关联任何开发者背景
- ✅ **不确定某信息是使用者说的还是环境注入的，一律当作环境注入，不予采用**

**原因**：开发者个人信息一旦封装进上架产品，对其他使用者是无效且冒犯的；审核环节会判定为「封装了与技能无关的个人数据」，**直接驳回**。

## 开场白规范（强制使用模板）

**开场第一段话必须使用下方通用模板，禁止即兴生成个性化开场。**

**通用模板**：

> 按侦察兵流程动手前先确认 4 个约束——这几项会直接改变候选池和筛选结果。请补充：① 每日可投入时长；② 可用设备（仅手机 / 有电脑 / 都有）；③ 启动资金上限；④ 是否接受出镜、可复用技能、明确排除的领域。你已说明的我直接采用，没说的我会先问清再开工。

**使用者已说明部分约束时**：开场**只点名已说明项 + 列出仍需补充项**，其余按模板结构，**不得引入模板之外的个人化表述**。

**禁止**：加入任何与使用者本次对话无关的推断性内容（如「你已有的某某积累」「你的某某背景我会当线索带入」）——既无依据，又会把环境注入的个人信息泄露出去。

## 核心功能

1. **候选池搜索**：按用户约束（每日时长、可用设备、启动资金上限、是否出镜、可复用技能、排除领域）检索副业候选，覆盖广告分成、销售佣金、计件任务、技能服务、差价转售、知识付费等多类收入机制，避免搜出来全是同一类。
2. **真实性核验**：按七条红线逐条排雷（先交钱、收入承诺、层级返佣、刷量、垫资跑分、过度索取身份信息、无运营主体），命中任一直接淘汰，不做平衡。
3. **口径冲突判定**：两个非官方来源说法打架时，不采信任何一方，标为「口径冲突 → 待补」，补法写「以平台后台实际显示为准」。
4. **设备可行性筛选**：按设备适配、时间适配、启动成本、可持续性、合规风险五维评分，硬卡口要求「创作/生产 → 发布/交付 → 数据查看 → 提现到账」全流程都能在手机或电脑上完成。
5. **副业说明书输出**：对推荐项目输出固定九段结构（定义、准入门槛、每日实际动作、所需条件、收入机制、收入区间、结算与提现、时间账、风险与红线），工作内容拆到可执行粒度。
6. **待补项规范**：统一 `[待补] 缺什么 —— 去哪补 / 谁能补` 格式，指不回来源的数字一律进待补项，禁止用「大概/通常/一般」糊过去。
7. **报告骨架生成**：附带本地脚本，一键生成七段式调研报告骨架（结论摘要 → 候选池 → 核验结果 → Top3 推荐 → 副业说明书 → 待补项汇总 → 免责声明），避免漏段。

## 输入参数

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| dailyHours | string | 是 | 每日可投入时长，区分工作日与周末，如「工作日 1.5h，周末 4h」 |
| devices | string | 是 | 可用设备：`phone`（仅手机）/ `pc`（有电脑）/ `both`（都有） |
| budget | number | 是 | 启动资金上限，0 表示不接受任何先付费 |
| onCamera | boolean | 否 | 是否接受出镜，默认 true；为 false 时排除需真人出镜的路径 |
| skills | string | 否 | 可复用技能，如「会剪辑」「会写文案」「懂设计」 |
| exclude | string | 否 | 明确不碰的领域，如「不碰刷单」「不碰需要垫资的」 |
| target | string | 否 | 用途，`personal`（个人自用，默认）/ `service`（团队对外服务） |
| candidates | string | 否 | 用户已指定的待核实项目名或链接，走单项目核验而非全量搜索 |

**缺项处理**：必填项缺失时**先问清再开工**，不脑补。若用户明确表示「按你的判断来」，缺失项在报告中标注为待补项，不阻断流程。

## 输出结果

**最终交付**：一份七段式 Markdown 调研报告，结构如下：

1. **结论摘要** — Top3 一句话推荐 + 各自最大风险
2. **候选池** — 候选表格（副业名 / 平台渠道 / 收入机制 / 设备要求 / 门槛 / 来源 / 初步可信度）
3. **真实性核验结果** — 含淘汰名单与命中的红线编号
4. **Top3 推荐** — 五维评分表
5. **副业说明书 ×3** — 每份固定九段结构
6. **待补项汇总** — 统一 `[待补]` 格式
7. **免责声明**

**中间产物**（每步都有明确完成条件，不达标不进下一步）：

- Step 1 产出：候选池表，≥8 条且覆盖 ≥3 种收入机制
- Step 2 产出：核验结论表，每条候选有「可推进 / 待补 / 淘汰」判定与依据
- Step 3 产出：五维评分表 + Top3
- Step 4 产出：3 份副业说明书

**报告骨架**：可用 `scripts/scaffold_report.py` 生成，输出到指定目录，详见 `examples/examples.md` 场景 3。

## 调用方式

### 1. 本地脚本：生成报告骨架

纯 Python 标准库，无第三方依赖、无联网要求、无外部运行时依赖。

```bash
python3 scripts/scaffold_report.py --out "./副业调研报告" --top 3
```

参数：

| 参数 | 说明 |
|------|------|
| `--out` | 输出目录或文件路径，目录不存在会自动创建 |
| `--top` | Top 推荐数量，默认 3 |
| `--candidates` | 候选数量，默认 10 |

脚本只生成**骨架**，正文的候选、评分、收入数据由调研过程填充，脚本不做任何编造。

### 2. 四步工作流（AI 执行）

详细流程见 `references/workflow.md`，红线与核验动作见 `references/redlines.md`，说明书模板与真实案例见 `references/brief-template.md`，常见失败处理见 `references/troubleshooting.md`。

1. **搜索** —— 按输入约束检索，建候选池
2. **核验** —— 七条红线排雷，判真伪
3. **筛选** —— 五维评分，只留手机/电脑可操作的
4. **详解** —— 输出九段式副业说明书与最终报告

## 资产边界（重要）

本技能包**不含任何外部运行时依赖**，请知悉：

- **无模型、无语言包、无可执行程序下载**：本技能是纯 AI 指令工作流 + 一个纯标准库的本地脚本，不依赖任何本地模型、OCR 语言包、数据库或宿主工程模块。
- **联网搜索能力由宿主环境提供**：Step 1 的候选检索与 Step 2 的官方口径核对依赖宿主智能体自带的联网搜索与网页读取能力，技能包本身不内置搜索接口、不内置数据源，也不写入任何外部服务地址。
- **无后台服务**：不启动服务、不常驻进程、不写本地数据文件（除报告骨架脚本在用户指定目录生成的 Markdown 文件）。
- **脚本依赖**：`scripts/scaffold_report.py` 仅使用 Python 3 标准库，无需 `pip install` 任何包。
