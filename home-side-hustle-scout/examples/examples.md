# 使用示例

以下示例展示家庭副业侦察兵的典型工作场景，供 WorkBuddy 智能体参考。

## 场景 1：从零调研家庭副业（完整四步流程）

**用户请求**：我想找一份在家能做的副业，请帮我调研并推荐手机或电脑就能操作的

**工作流**：

1. **收集约束**：若用户未说明时长、设备、资金上限，先问清再开工。
2. **Step 1 搜索**：按六类收入机制分头检索，建候选池 ≥8 条。
3. **Step 2 核验**：七条红线逐条排雷，官方口径优先，口径冲突标待补。
4. **Step 3 筛选**：五维评分，只保留「创作 → 交付 → 数据 → 提现」全流程能在手机或电脑上跑通的，输出 Top3。
5. **Step 4 详解**：每份九段式副业说明书 + 七段式最终报告。

**输出（报告结构）**：

```
1. 结论摘要 —— Top3 一句话 + 各自最大风险
2. 候选池 —— 候选表格
3. 真实性核验结果 —— 含淘汰名单与红线编号
4. Top3 推荐 —— 五维评分表
5. 副业说明书 ×3 —— 九段结构
6. 待补项汇总 —— [待补] 格式
7. 免责声明
```

**解读**：结论前置，用户第一眼就能看到可选项与风险，再往下看依据。

## 场景 2：核实单个项目是否靠谱

**用户请求**：帮我核实这个副业项目是不是真的，会不会是骗局

**工作流**：

1. 用户提供项目名或链接，**跳过全量搜索**，直接进入 Step 2 核验。
2. 按七条红线逐条检查，重点查 R1（先交钱）、R3（层级返佣）、R5（垫资跑分）、R7（无主体信息）。
3. 查官方口径、运营主体、退出机制、负面投诉。
4. 输出**单项目核验结论**：

```
项目：<项目名>
判定：可做 / 有条件可做 / 不建议（淘汰）
依据：<来源等级 + URL，逐条列出>
命中红线：<编号；无则写「无」>
提现规则：<已核实 / 待补 / 一票否决>
风险提示：<≥3 条>
待补项：[待补] ...
```

**解读**：单项目核验不建候选池、不做五维评分，聚焦「能不能做」这一个结论，但依据与红线留痕标准不变。

## 场景 3：生成调研报告骨架

**用户请求**：先把报告框架搭出来，我后面自己填内容

**调用**：

```bash
python3 scripts/scaffold_report.py --out "./副业调研报告" --top 3
```

**输出**：

```
副业调研报告/
└── 副业调研报告.md
```

报告骨架内容（七段，含各段占位与填写提示）：

```markdown
# 家庭副业调研报告

## 1. 结论摘要
> 待填：Top3 一句话推荐 + 各自最大风险

## 2. 候选池
> 待填：候选表格（副业名 / 平台渠道 / 收入机制 / 设备要求 / 启动门槛 / 来源 / 可信度）

## 3. 真实性核验结果
> 待填：含淘汰名单与命中红线编号

## 4. Top3 推荐
> 待填：五维评分表（设备 / 时间 / 成本 / 持续 / 合规）

## 5. 副业说明书
> 待填：每份九段结构（定义 / 门槛 / 每日动作 / 所需 / 收入机制 / 收入区间 / 结算提现 / 时间账 / 风险）

## 6. 待补项汇总
> 待填：统一 [待补] 格式

## 7. 免责声明
（已预置标准免责声明文本）
```

**参数说明**：

| 参数 | 说明 | 默认值 |
|---|---|---|
| `--out` | 输出目录或文件路径，目录不存在自动创建 | 当前目录 |
| `--top` | Top 推荐数量 | 3 |
| `--candidates` | 候选池条目数量 | 10 |

**解读**：脚本只生成**骨架**，不做任何编造。正文的候选、评分、收入数据由调研过程填充。

## 场景 4：约束条件下筛选

**用户请求**：我每天只有 2 小时、只有手机，帮我筛出能做的副业并说明工作内容和收入

**工作流**：

1. 约束锁定：`dailyHours = 2h`、`devices = phone`、按用户未说明的项先追问。
2. Step 3 筛选时，**设备适配**维度权重最高，任何需要电脑配合或线下环节的候选降权或淘汰。
3. **时间适配**维度：单次 ≤30 分钟可推进的优先，必须固定时段在线的（直播坐班、客服排班）淘汰。
4. 输出时明确说明：在该约束下可选项有限，如需更多选择可放宽哪一项约束。

**解读**：不放宽用户约束凑数，如实说明限制并给出可放宽的方向，由用户拍板。
